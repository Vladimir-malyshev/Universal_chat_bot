# Задача 011: Улучшение 웹-поиска (Глубокий поиск через Jina AI)

## Проблема
Текущая реализация инструмента поиска (`search_web` в `services/tools.py`) работает по принципу поверхностного парсинга: она делает запрос к DuckDuckGo и возвращает только заголовки и короткие сниппеты из выдачи. Это часто приводит к тому, что модель получает "мусор" или обрывки фраз, по которым невозможно дать глубокий и точный ответ.

## Ожидаемый результат
Необходимо усовершенствовать инструмент поиска так, чтобы он не просто брал текст из поисковой выдачи, но и переходил по найденным ссылкам, извлекая оттуда полезный контент. 
Для этого планируется использовать сервис **jina.ai/reader/** (преобразует любую веб-страницу в чистый LLM-friendly Markdown).

## План работ

1. **Создание тестового стенда (Изолированное тестирование связки DDGS + Jina AI):**
   - Написать отдельный скрипт (например, `Tasks/examples/test_jina_reader.py`).
   - Реализовать функцию поиска через DuckDuckGo (получение топ-3 ссылок).
   - Реализовать функцию чтения контента по этим ссылкам через API Jina (просто добавить `https://r.jina.ai/` перед URL).
   - Запустить скрипт с разными типами сложных запросов (новости, аналитика, технические статьи) и визуально или с помощью LLM оценить качество и объем получаемого текста.
   - Оценить время задержки (latency) такого двойного запроса (DDGS + Jina по 3 ссылкам может занять время).

2. **Интеграция в основной код (после успешных тестов):**
   - Обновить функцию `search_web` в `services/tools.py`.
   - Добавить асинхронные HTTP-запросы (например, через `aiohttp` или `httpx`) к Jina AI Reader для парсинга найденных URL.
   - Ограничить объем возвращаемого текста (чтобы не превысить контекстное окно модели, обрезать слишком длинные статьи).
   - Изменить системный промпт (описание `SEARCH_TOOL_SCHEMA`), чтобы модель понимала, что она получит полные статьи, а не просто сниппеты.

3. **Тестирование готового пайплайна:**
   - Запустить бота и попросить его проанализировать свежую статью или сложную новость, для которой обязательно нужен переход по ссылке.
   - Убедиться, что время ожидание ответа остается в разумных пределах, либо добавить промежуточные сообщения в UX (e.g. "Читаю статью...").
