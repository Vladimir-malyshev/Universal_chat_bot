ПРOMПТ ДЛЯ AI-АГЕНТА: Инициализация системы Персон (Persona Management)

Role: Senior Backend Engineer / Architect

Context: В нашем омниканальном ядре на FastAPI мы внедряем динамическую систему «Персон» (Personalities). Каждая персона определяет поведение ИИ и его базу знаний.

Data Structure:

    В корне проекта есть файл person.set. В нем записано только имя текущей активной персоны (например, Morpheus).

    В корне есть директория person/. Внутри неё находятся папки, чьи имена соответствуют именам персон.

    В каждой папке персоны лежат два файла:

        instructions.txt — системные инструкции (ToV, стиль общения).

        knowledge_base.txt — база знаний и контекстные данные для этой роли.

Task: Реализовать модуль services/persona_service.py и интегрировать его в core/orchestrator.py.

Requirements:

    Persona Loading (Singleton/Cache):

        Создай сервис, который при старте приложения (или при первом вызове) читает person.set.

        На основе этого имени он должен загрузить содержимое instructions.txt и knowledge_base.txt из соответствующей папки.

        Важно: Содержимое файлов должно кешироваться в памяти. Недопустимо читать файлы с диска при каждом входящем вебхуке.

    Dynamic Update: Реализуй метод для принудительного обновления кеша (refresh), если мы вручную изменим person.set.

    Orchestrator Integration:

        В orchestrator.py функция process_universal_message должна запрашивать у persona_service текущие инструкции.

        Эти данные должны объединяться в единый System Prompt для LLM.

        Формат промпта: [Instructions] \n\n База знаний: [Knowledge Base].

    Error Handling: Если папка или файлы, указанные в person.set, отсутствуют, система должна откатываться к «Дефолтной персоне» (просто вежливый помощник) и логировать ошибку.
